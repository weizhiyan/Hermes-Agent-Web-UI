# 技能中心逻辑说明

这份文档用于说明 Hermes WebUI「技能中心」的产品逻辑、数据扫描规则、筛选规则和文件预览/编辑规则，方便后续让 Agent 或开发者按同一套逻辑实现和维护。

## 1. 核心原则

技能中心左侧展示的是「Skill 列表」，不是文件夹树。

外置 Skill 的识别规则是：

> `D:\HermesData\skill` 目录下的第一层文件夹，才是一个 Skill。

右侧才展示该 Skill 文件夹内的文件内容。

不要把 Skill 内部的子文件夹继续展开成左侧的技能层级。

---

## 2. 左侧筛选入口

技能中心只需要三个筛选入口：

1. `全部`
2. `内置`
3. `我的 Skill`

不需要保留以下筛选：

- `Hub`
- `本地`
- `已修改`

这些入口会增加理解成本，而且当前场景中没有必要。

---

## 3. 筛选逻辑

筛选入口与数据字段的对应关系如下：

```js
全部       -> source = null
内置       -> source = 'builtin'
我的 Skill -> source = 'external'
```

推荐实现：

```js
function setSkillFilter(source) {
  state.skillFilter.source = source || null
  renderSkillList()
}
```

不要使用「点击同一个 tab 再取消筛选」的逻辑。

原因是用户会误以为当前 tab 仍然生效，但实际列表可能已经切换成全部或空状态，容易造成困惑。

推荐逻辑是：

```js
if (filter === 'all') {
  show all skills
}

if (filter === 'builtin') {
  show skills where source === 'builtin'
}

if (filter === 'external') {
  show skills where source === 'external'
}
```

---

## 4. 左侧列表层级

左侧列表必须是扁平结构。

不要按 `category` 再分组。

错误示例：

```text
WEBUI
└─ WebUI更新

设计写作
└─ design-writing-polisher
```

正确示例：

```text
全部
- WebUI更新
- design-writing-polisher

内置
- 代码审查
- 图像生成

我的 Skill
- WebUI更新
- design-writing-polisher
```

也就是说，左侧直接展示技能名称，不展示 `WEBUI > WebUI更新` 这种两层结构。

---

## 5. 外置 Skill 扫描规则

外置 Skill 根目录：

```text
D:\HermesData\skill
```

只扫描该目录下的第一层文件夹。

示例：

```text
D:\HermesData\skill
├─ WebUI更新
│  └─ SKILL.md
├─ design-writing-polisher
│  └─ SKILL.md
```

应该识别成：

```text
WebUI更新
design-writing-polisher
```

不要继续递归扫描二级、三级目录。

错误示例：

```text
obsidian-skills
└─ skills
   ├─ obsidian-markdown
   ├─ defuddle
   ├─ json-canvas
```

如果 `obsidian-skills` 是放在外置 Skill 根目录下的第一层文件夹，那么它本身才是一个 Skill。

不要把 `obsidian-markdown`、`defuddle`、`json-canvas` 自动拆成左侧多个 Skill，除非用户把它们各自移动到外置 Skill 根目录的第一层。

---

## 6. 右侧详情区

点击左侧某个 Skill 后，右侧展示该 Skill 的详情。

右侧应包含：

1. 技能名称
2. 技能描述
3. 技能来源
4. 文件夹路径
5. 启用 / 停用开关
6. 技能文件列表
7. 文件内容查看区

文件名要完整显示。

不要把长文件名截断成 `...`。

可以换行显示完整路径或完整文件名。

---

## 7. 文件内容区

文件内容区需要两个模式：

1. `预览`
2. `源码`

默认使用 `源码` 模式。

原因：

- 用户可以直接编辑 Skill 文件。
- 不需要再点击额外的「编辑」按钮。
- 编辑后点击保存即可。

逻辑如下：

```js
if (mode === 'source') {
  show textarea
  allow edit
  show save button
}

if (mode === 'preview') {
  render markdown
  hide save button
}
```

---

## 8. 源码模式

源码模式用于编辑 Skill 文件。

要求：

- 使用 `textarea`
- 默认可编辑
- 显示保存按钮
- 保存时写回对应文件

示例：

```js
<textarea id="skFileEditor">${content}</textarea>
<button onclick="saveSkillFile()">保存</button>
```

---

## 9. 预览模式

预览模式用于查看 Markdown 渲染效果。

要求：

- 使用 Markdown 渲染器
- 不显示保存按钮
- 不允许直接编辑

示例：

```js
<div class="markdown-body">
  {renderMarkdown(content)}
</div>
```

---

## 10. 文件编辑区高度

文件编辑区高度应该根据屏幕高度自适应。

不要写死很小的高度。

推荐 CSS：

```css
.skill-file-editor {
  width: 100%;
  height: clamp(520px, calc(100vh - 390px), 920px);
  min-height: 420px;
  resize: vertical;
}
```

说明：

- 小屏幕下不低于 `420px`
- 中等屏幕下根据 `100vh` 自动计算
- 大屏幕下最高不超过 `920px`

这样可以保证用户输入或查看长 Skill 文件时，不会只看到很小一块内容。

## 11. 刷新 Skill 逻辑

技能中心需要一个 `刷新 Skill` 按钮。

点击后执行：

1. 重新请求 `/api/skills`
2. 后端重新扫描外置 Skill 文件夹
3. 前端刷新 Skill 列表
4. 如果当前选中的 Skill 仍然存在，则保持选中
5. 如果当前选中的 Skill 已不存在，则清空选中状态

推荐伪代码：

```js
async function refreshSkills() {
  const skills = await apiGet('/api/skills')

  state.skills = skills.map(normalizeSkill)

  if (
    state.selectedSkill &&
    !state.skills.some(skill => skill.id === state.selectedSkill)
  ) {
    state.selectedSkill = null
  }

  renderPage()
}
```

---

## 12. 数据标准化

从接口拿到 Skill 后，需要做一次标准化。

推荐：

```js
function normalizeSkill(skill) {
  return {
    ...skill,
    description: skill.description || skill.desc || '',
    category: skill.category || skill.tags?.[0] || '未分类',
    enabled: skill.enabled !== undefined ? skill.enabled : skill.on !== false,
  }
}
```

---

## 13. source 字段约定

Skill 来源字段建议固定为：

```js
builtin  // Hermes 内置 Skill
external // 用户放在外置目录里的 Skill
custom   // WebUI 内手动创建的自定义 Skill，可选
```

当前技能中心主筛选只需要：

```js
builtin
external
```

即：

```text
内置
我的 Skill
```

## 14. 常见错误

### 14.1 把 Skill 当文件夹树展示

错误：

```text
WEBUI
└─ WebUI更新
```

正确：

```text
WebUI更新
```

### 14.2 递归扫描子目录

错误：

```text
obsidian-skills/skills/obsidian-markdown
obsidian-skills/skills/defuddle
obsidian-skills/skills/json-canvas
```

正确：

```text
obsidian-skills
```

除非用户把 `obsidian-markdown`、`defuddle`、`json-canvas` 分别放到外置 Skill 根目录第一层。

### 14.3 缺少全部 tab

错误：

```text
内置 | 我的 Skill
```

正确：

```text
全部 | 内置 | 我的 Skill
```

### 14.4 源码模式不可编辑

错误：

```text
点击编辑后才能改
```

正确：

```text
源码模式默认就是可编辑状态
```

---

## 15. 最终一句话总结

技能中心左侧是扁平的 Skill 列表，不是文件夹树；外置目录的一层文件夹才是 Skill，右侧才展示这个 Skill 文件夹里的文件内容，并提供预览 / 源码两种查看方式。
