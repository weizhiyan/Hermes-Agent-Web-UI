# Hermes Agent UI 重设计计划

## 目标

- 整体气质更接近 Claude：克制、温和、留白充足、内容优先。
- 聊天工作区更接近 Codex：强调执行流、工具调用、文件/预览和上下文状态。
- 主视觉保持黑白极简，默认浅色模式。
- 保留全部现有功能，但统一视觉语言和组件规范。

## 设计原则

1. **浅色优先**
   - 默认主题为 light。
   - dark 作为次级模式，仅做 token 反转，不引入第二套视觉语言。

2. **黑白极简**
   - 主操作使用黑白对比。
   - 彩色仅用于状态、选中、提示和少量语义强调。
   - 避免大面积渐变、强阴影和高饱和装饰色。

3. **内容优先**
   - 聊天内容、工具调用、文件预览、记忆和历史记录都应更易扫描。
   - 减少界面噪音，让信息层级更清楚。

4. **组件统一**
   - 所有页面复用同一套按钮、输入框、卡片、弹窗、标签、下拉和面板。
   - 禁止同类控件出现多套视觉规则。

## 视觉方向

- **背景**：温和偏暖的浅白，不用纯白。
- **正文**：接近黑色。
- **次级文字**：中性灰。
- **分割线**：极浅灰，尽量弱化边界。
- **卡片**：低对比、轻边框、少阴影。
- **主按钮**：黑底白字或白底黑字，统一尺寸与圆角。

## 组件规范

### 基础组件

- `Button` / `IconButton`
- `Input` / `Textarea`
- `Select` / `Dropdown`
- `Tabs`
- `Card`
- `Badge`
- `Modal`
- `PanelHeader`

### 业务组件

- `SessionItem`
- `Message`
- `ToolCallBlock`
- `Composer`
- `PreviewPanel`
- `SettingsRow`
- `HistoryCard`

## 页面策略

### 聊天页

- 作为主工作台，视觉层级最高。
- 消息流更像工作记录，而不是纯聊天气泡。
- 工具调用、思考过程、文件引用、预览入口统一折叠/展开样式。
- 输入区作为固定 composer，按钮收敛为少量统一图标按钮。

### 侧边栏

- 保留功能，但降低视觉存在感。
- 会话项、当前 Agent、历史入口使用同一种列表样式。
- 选中态用轻量背景和细边框表达。

### 设置/模型/记忆/文件/日志

- 统一成“列表 + 详情”或“卡片 + 面板”结构。
- 减少页面间风格差异。
- 统一标题、说明、操作区和空状态。

## 组件落地顺序

1. 设计 tokens：颜色、圆角、阴影、间距、字号
2. 基础组件：按钮、输入、卡片、标签、弹窗
3. 聊天页：消息、composer、工具调用、预览面板
4. 侧边栏与会话列表
5. 设置/模型/记忆/文件/日志统一
6. 深色模式按同一套 token 反转处理

## 当前优先修复的问题

- 不同下拉框样式不一致。
- 按钮圆角、间距、边框、hover 状态不统一。
- 卡片和面板阴影过多，层级不清晰。
- 聊天区、设置区、历史区视觉语言割裂。
- 默认深色模式与目标风格冲突。

## 建议的第一步实现

- 先把 `index.html` 中的全局 CSS 变量重构成 Hermes tokens。
- 再抽出一组统一的基础组件类。
- 最后按页面逐步替换现有散落样式。
