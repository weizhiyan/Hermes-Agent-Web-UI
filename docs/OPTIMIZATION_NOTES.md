# Hermes Agent WebUI 优化说明

这份文档记录当前 WebUI 相比普通 Hermes Agent WebUI / 通用 WebUI 的优化方向、已经完成的改动，以及后续仍可继续优化的点。

## 1. 当前优化目标

核心目标是：

```text
普通聊天更快，复杂任务仍保留 Hermes Agent 的真实执行能力。
```

也就是：

- 日常聊天、问答、润色、方案讨论：优先直连模型 API。
- 文件、命令、代码、项目任务：自动切换 Hermes Agent。
- 记忆、偏好、Agent Profile、相关 Skill：仍由 WebUI 后端统一注入。
- 生成图片、输出图片、Markdown 历史：统一走可配置的外部数据目录。

## 2. 已完成优化

### 端口统一

默认端口统一为：

```text
3381
```

不再混用 `8787`。

### 自动路由

当前默认路由为 `auto`：

```text
普通聊天  -> direct
复杂任务  -> hermes
```

设置页支持：

- 自动
- 始终直连
- 始终 Hermes Agent

执行过程面板会显示当前消息选择了哪个通道。

### 直连模型加速

普通聊天不再每次启动 Hermes CLI / WSL，而是走：

```text
浏览器 -> WebUI 后端 -> 模型 API
```

这样能明显降低首包等待时间。实测短问答通常在 1 到 2 秒左右完成，具体取决于模型服务商和网络。

### Hermes API Server 通道

当设置了 Hermes API Server URL 后，复杂任务会优先尝试：

```text
WebUI -> Hermes API Server -> Hermes Agent
```

如果 API Server 不可用，会自动回退到 Hermes CLI，并在执行过程里显示回退原因。

### 按需 Skill 注入

普通聊天不再全量注入所有 Skill，而是按当前问题匹配相关 Skill。这样可以减少 Prompt 长度，提高首 token 速度，也避免无关 Skill 干扰回复。

### 记忆与数据目录外置

设置页支持配置：

- 数据根目录
- 记忆目录
- 图片目录
- 历史 Markdown 目录
- 输出 Markdown 目录

推荐目录：

```text
D:\HermesData
```

如果记忆目录移动到其他盘，只要在设置页修改路径，WebUI 会自动读取新路径。

### 执行过程真实化

不再使用假的“思考中”占位。现在显示真实事件：

- SSE 连接建立
- 路由选择
- Hermes API Server 连接
- 回退 Hermes CLI
- 首 token
- 工具调用
- 完成或错误

### `<think>` 解析修复

支持解析模型输出中的：

```xml
<think>...</think>
```

但直连模型默认不展示原始 `reasoning_content`，避免输出冗长或敏感推理内容。

### 模型测速

模型库新增“测速”按钮，后端接口会测量：

- 首包耗时
- 总耗时
- 输出字符数
- 简短响应内容

测速结果会显示在模型列表中，方便选择更快的普通聊天模型。

### 失败回退模型

模型场景新增“失败回退”。当普通对话主模型失败时，可以自动尝试备用模型，并在执行过程里显示切换事件。

### Agent 反问弹窗

新增类似 Claude Code 的用户确认通道：Agent 或后端任务可以通过 `/api/sse/ask` 向当前 WebUI 推送问题，前端弹出 Agent 提问面板，用户选择或填写补充说明后，结果会回传给后端。

默认 Agent 规则也已写入该接口说明，因此 Agent 在读取规则后会知道何时调用弹窗、如何等待 answers，以及失败时如何降级为聊天提问。

这个能力适合用于：

- 任务开始前确认目标。
- 高风险操作前请求用户选择。
- 信息不足时让 Agent 主动追问。
- 多方案任务中让用户选择方向。

### 工具权限与安全审批

现在高风险命令不再只是后台记录或直接拦截。对于 `git push`、`git reset --hard`、`git clean`、`npm publish`、`docker system prune` 等风险命令，WebUI 会先弹出确认面板；用户选择“确认执行”后才会真正运行，取消、超时或没有 WebUI 客户端连接都会阻止执行。

设置页新增“工具权限与安全”：

- 安全模式：阻止危险命令，允许安全命令。
- 严格模式：高风险命令也会被拦截。
- 关闭拦截：仅在你明确知道风险时使用。
- 审批日志：记录命令、工作目录、风险等级和阻止原因。

默认会阻止例如：

- `rm -rf`
- `Remove-Item -Recurse -Force`
- `format`
- `diskpart`
- `shutdown`
- `Set-ExecutionPolicy`
- `curl | sh`
- `wget | bash`

同时会标记例如：

- `git push`
- `git reset --hard`
- `git clean`
- `npm publish`
- `docker system prune`

这些属于可能修改远程或清理本地数据的高风险命令。

## 3. 当前逻辑与竞品差异

### 与普通 WebUI 的差异

普通 WebUI 通常只负责聊天和模型配置。Hermes Agent WebUI 额外保留：

- Agent 执行能力
- 本地文件和命令任务
- Skill 注入
- 外部记忆路径
- Markdown 输出与历史归档
- 本地安全策略

因此它不只是聊天界面，而是本地 AI 工作台。

### 与纯 Hermes Agent CLI 的差异

CLI 更适合开发者直接执行任务，但普通聊天会有启动和上下文准备开销。WebUI 当前通过自动路由解决这个问题：

- 普通聊天走直连，速度更接近通用 WebUI。
- 复杂任务走 Hermes，保留 Agent 能力。

### 与官方/热门竞品的差异

目前已经接近竞品的部分：

- 普通聊天速度
- 流式输出
- 模型配置
- 记忆路径配置
- 任务过程展示
- 本地数据归档

仍可继续追赶的部分：

- 更细的工具审批交互，例如每次高风险操作弹窗确认。
- 更成熟的插件/Skill 市场。
- 更强的多模型路由，例如按任务类型自动选择最快或最便宜模型。
- Hermes Agent 常驻服务，减少复杂任务冷启动时间。
- 更完整的更新器，例如 UI 内检查新版本、下载更新、查看发布说明。

## 4. 性能瓶颈判断

如果普通聊天仍慢，优先检查：

1. 当前是否走了 `direct` 通道。
2. 模型 API 首包是否慢。
3. 是否注入了过多历史、Skill 或知识库片段。
4. 是否启用了慢模型作为普通聊天模型。
5. 网络或服务商是否不稳定。

如果复杂任务慢，通常是因为：

- Hermes CLI / WSL 冷启动。
- Agent 初始化上下文。
- 工具调用和项目扫描本身耗时。
- 模型深度推理较慢。

复杂任务想继续提速，最佳方向是 Hermes Agent 常驻 API Server，而不是每次 spawn CLI。

## 5. 后续建议

优先级从高到低：

1. UI 内更新中心：检查 GitHub 最新版本、显示 changelog、提示本地改动风险。
2. 工具审批弹窗：高风险命令先进入待确认队列，而不是简单拦截。
3. Skill 元数据：为每个 Skill 增加触发词、适用场景、优先级。
4. 常驻 Hermes Worker：降低复杂任务冷启动时间。
5. 模型自动选择：根据测速结果自动选择最快的普通聊天模型。
6. 数据备份导出：一键打包记忆、设置、模型配置和历史索引。


### Skill 触发词与命中可视化

Skill 中心保留现有 Skill 管理逻辑，新增触发词、优先级和自动触发词建议。对话时后端会把本次匹配到的 Skill 通过流式性能事件传给前端，执行过程会显示“命中 Skill”，并标出触发词或命中原因，便于判断是否误触发或漏触发。


### 备份导出

设置页新增“一键备份导出”。后端会在数据目录 `backups` 下生成 JSON 备份文件，包含设置、模型配置、Skill、聊天索引、网关配置和数据目录文件清单。敏感字段会脱敏，避免备份文件直接泄露 API Key。


### 模型测速后自动选择

模型配置页新增“使用最快普通模型”。它基于已有测速结果选择首包时间最短的聊天模型，并只更新普通对话场景，避免影响深度推理、图像和回退模型配置。
